# 一致性梳理审计（webnovel-audit）

目的：**梳理已有内容，暴露并修复逻辑矛盾，让后续章节站在干净的地基上。** 审计阶段只读；修复方案经用户确认后才动文件。

## 触发时机

- 每写完约 5 章（默认周期，可由用户调整）。
- 每卷收尾前（必做，加做"卷末对照"）。
- 用户要求："梳理一下 / 查查逻辑 / 前边对不上了"。
- 用户问："还要写多久 / 能不能写完 / 现在进度到哪"——此时第七维必须出结论，且**先读 .story-system/project_spec.json 的 progress 与 deviations**，不要凭印象回答。
- 写作中即时察觉矛盾（可做聚焦小审计，只查相关链路）。

## 审计七维

### 1. 伏笔账本
数据源：.story-system/events/ 全部 `open_loop_created` vs `open_loop_closed`，对照 大纲/总纲.md 伏笔表。
- **账龄榜**：超过 expected_payoff 仍未回收的伏笔，按超期排序——逐条决定"近期回收 / 延后并修订 expected_payoff / 降级放弃"。
- **无主伏笔**：events 里有、总纲伏笔表里没有 → 补登记。
- **幽灵回收**：正文实际回收了、事件流没记 → 补记 open_loop_closed。
- **重复埋设**：同一伏笔多条 created → 合并。

### 2. 时间线
数据源：各章时间锚点（正文/摘要/events 中的时间表述）。
- 串联成全卷时间线，检测日期/昼夜/时长/年龄/季节互斥。
- 与 大纲/第N卷-时间线.md 对照，偏差登记。

### 3. 人物状态漂移
数据源：`character_state_changed` 事件流 + 正文。
- 每个命名人物逐章追踪：位置/伤势/能力/持有物/关系/知情范围。
- 检测：无铺垫跳跃（时空瞬移）、知情穿越（说出不可能知道的信息）、能力越界（设定外能力/超等级）、称谓漂移。

### 4. 设定一致性
数据源：`world_rule_revealed` 事件 vs 设定集/世界观.md、力量体系.md。
- 规则冲突（两条规则打架）、规则突变（升级无铺垫）、代价豁免（金手指/规则代价被悄悄免掉）。

### 5. 大纲-正文偏差
数据源：详细大纲 CBN vs 实际正文。
- 逐项登记偏差 → 与用户逐条决定：写回大纲（大纲迁就正文）还是修正文（正文迁就大纲）。
- 结构性偏差（整条线改向）→ 更新卷纲/总纲，并在 大纲/ 目录留下写回记录。

### 6. 反模式复犯
数据源：最近 5 章正文 vs .story-system/anti_patterns.md。
- 逐条扫；复犯 ≥2 次的反模式提升警戒级，写入下章细纲的"显式规避"清单。
- **新书开篇专项（前 10 章加查，新人避坑清单）**：
  - 开篇堆人名：前三章出现 ≥4 个具名人物且无代称处理（"黑衣人""掌柜"类）→ 登记，要求只聚焦一个核心主角。
  - 开篇讲设定：连续两段以上的设定直述（"三族五界""修炼等级"式说明文）→ 登记，要求改藏进剧情。
  - 环境描写炫技：单章环境/景物描写超过 300 字且不烘托情绪、不推动剧情 → 登记（"屋里有股血腥味"优于五段日落描写）。
  - 黄金三章体检：第一章是否冲突前置第一句"出事"（而非设定/环境/内心独白开场）；第二章金手指是否直接关联主角困境且章尾卡在破局前一秒；第三章是否建立"期待感闭环"（短期目标+主角变化+反派叫嚣）。任一不达标 → 登记为 ⛔ 级，建议返工。

### 7. 体量与进度

数据源：.story-system/project_spec.json + .story-system/chapters/*.json + 各章实算字数 + .story-system/structure_map.json。

- **字数达成率**：实际总字数 vs `scale.target_words`；已写章数 vs `scale.target_chapters`。
- **卷级达成率**：每卷 `words_actual` vs `words_budget`，偏差 >10% 登记。
- **进度对账**：按 `delivery.words_per_day` 与 `delivery.chapters_per_day`，当前进度是超前还是落后；落后 >10% → 结论里给加速方案。
- **卷均章数偏离**：实际每卷章数 vs `scale.volume_plan` 声明值。
- **注水检测**：
  - 连续 2 章以上"功能相同"（同一套路、同一爽点类型、同一场景结构）→ 登记为注水嫌疑；
  - 连续 3 章无人物状态变化、无关系变化、无规则揭示 → 登记为节奏塌陷；
  - 大纲里已登记但正文未兑现的爽点里程碑 → 登记。
- **规格漂移**：正文实测章长与 `scale.chapter_words` 的长期偏离（连续 5 章低于下限 → 登记为基线执行失败）。
- **结构位置兑现**：对照 .story-system/structure_map.json，检查每个 beat 的 `must_happen` 是否在指定章号附近真的发生了；连续 10 章落在两个相邻 beat 之间（无 beat 归属）→ 登记为"结构位置缺失"，这是中段塌陷的早期信号。
- **卷语义变化**：相邻两卷的 `volume_pivot` 是否真的不同（只看章号切分、语义无变化的卷 → 登记）。
- **机械感**：跨全卷统计 `compliance.style_taboo` 里的固定短语出现次数；同一短语在 3 章以上重复出现 → 登记；连续 ≥15 字重复串 → 登记。

> 第 7 维不只回答"写了多少"，还要回答"该写多少、有没有注水、是不是写到了结构位置上"。
> 长篇模型的两大公认缺陷是"写不出任意长度且不失连贯"和"不会把故事带到真正的结局"，而一致性错误在实测中**倾向于出现在叙事中段**——所以中段塌陷必须有一个可检的早期信号，而不是等到卷末才发现。

## 卷末对照（卷收尾前加做）

- 本卷卷末高潮 vs 卷纲骨架承诺：是否兑现。
- 下一卷开卷钩子是否已在本卷末埋好。
- 主角状态快照 vs 总纲成长线节点：是否对齐。
- 跨卷伏笔：本卷应交付的一层是否交了。
- **体量交付**：本卷承诺章数是否写完、实际字数 vs `words_budget` 偏差、下一卷章数是否与 `scale.volume_plan` 一致。
- **进度健康度**：全书已完成字数占比、距目标完本周期的剩余量；是否需要调整总卷数或总章数（若要调整 → 走 project_spec 的 `deviations` 记录 + 用户拍板）。

## 报告与修复

产出：审查报告/梳理报告-YYYYMMDD.md
结构：总览（问题数/分级统计/结论）→ **七维问题清单**（每条：位置 + 证据 + 修复方向）→ 伏笔台账快照 → 时间线快照 → **体量与进度看板**（已写章数/字数/目标/达成率/进度偏差/注水嫌疑数/结构位置缺口数）。

结论分级：✅ 可继续连载 ｜ ⚠️ 建议先修再写 ｜ ⛔ 必须先修。

修复流程：
1. 报告呈给用户，逐条确认修复方案。
2. 先修台账与设定文件（events/伏笔表/设定集）——它们是事实来源。
3. 再修正文（正文改动需用户点头；大改给前后对照）。
4. 复查修复项，在报告尾部追加修复记录与日期。
5. 若第 7 维给出体量调整建议（改总章数 / 改卷划分 / 改更新量），走 project_spec 的 `deviations` 流程：只增不删记录 → 用户拍板 → 同步改 spec → 再改总纲/卷纲 → 回归校验（Σ章数、Σ字数）。
